# Audit Repository 31 Juli 2026

## Status

Dokumen ini adalah sumber status audit untuk seluruh repository dan tiga APK
Retail, Wholesale, serta Culinary. Status `Diperbaiki` berarti perubahan sudah
masuk ke patch audit, tetapi tetap harus dibuktikan oleh GitHub Actions dan
pengujian perangkat sebelum rilis.

## Diperbaiki dalam patch ini

- layout katalog compact tidak lagi dibatasi tinggi 76 dp;
- pemilih file restore tidak mengunci sesi Owner saat Android membuka file picker;
- produk bervarian dapat dipilih pada penyesuaian stok dan pembelian;
- edit produk mempertahankan `stockTrackingEnabled` dan ambang stok sebelumnya;
- pembuatan pekerja harian dan tarif awal berlangsung dalam satu transaksi Room;
- nama usaha aktif dipakai saat snapshot transaksi dan struk disimpan;
- indikator stok landing menghitung stok varian;
- CI memeriksa unit test, kompilasi androidTest, debug APK, release build, dan lint
  untuk ketiga flavor;
- README dan dokumen arsitektur diselaraskan dengan versi 0.3.1.

## Masih terbuka dan tidak boleh dianggap selesai

### Transaksi dan persediaan

- alur void, refund, return, atau pembatalan transaksi dengan audit trail;
- pembelian Grosir belum memilih satuan dan `factorToBase`;
- validasi stok gabungan beberapa baris keranjang Grosir baru terjadi saat checkout;
- kasbon pekerja belum dicatat sebagai arus kas saat uang diberikan.

### Struk dan ekspor

- PNG struk Kuliner belum memuat seluruh topping dan catatan;
- PNG transaksi kredit perlu menampilkan DP dan sisa piutang secara eksplisit;
- model struk belum menyimpan nama pelanggan.

### Keamanan dan distribusi

- backup ZIP belum terenkripsi atau diautentikasi;
- kebijakan Android backup perlu `dataExtractionRules` yang eksplisit;
- PIN Owner belum memiliki retry limit atau cooldown;
- release signing dan distribusi APK release belum dikonfigurasi;
- repository belum mempunyai LICENSE, sehingga belum dapat disebut open source
  dengan hak penggunaan yang jelas.

### Dokumentasi dan QA

- connected Android test wajib dijalankan terpisah untuk Retail, Wholesale, dan Culinary;
- klaim verifikasi lama yang hanya memakai task unit test tidak membuktikan `androidTest`;
- dokumen UI lama perlu ditandai sebagai historis atau diperbarui;
- visual QA pada viewport perangkat nyata masih diperlukan.

## Gerbang rilis

Rilis tidak boleh dinyatakan siap sebelum:

1. seluruh job GitHub Actions hijau;
2. connected Android test lulus pada tiga flavor;
3. alur transaksi tunai, kredit, stok varian, pembelian, dan restore diuji di perangkat;
4. konfigurasi signing release ditetapkan;
5. masalah terbuka yang memengaruhi uang atau stok diputuskan dan didokumentasikan.
